## 🛠 Локальная разработка (без Docker)

### 4. Клонируйте свой форк
- Откройте терминал (командную строку) и перейдите в папку, где хранятся проекты (например, `C:\Projects` или `~/Projects`):
  ```bash
  cd C:\Projects   # или cd ~/Projects
  ```
- Склонируйте репозиторий (ссылку скопируйте на странице вашего форка, нажав **Code → Local → HTTPS**):
  ```bash
  git clone https://github.com/ваш-username/task-manager.git
  cd task-manager
  ```

### 5. Откройте проект в VS Code
```bash
code .
```

### 6. Настройте виртуальное окружение
- В VS Code откройте встроенный терминал (**Terminal → New Terminal**) и выполните:
  ```bash
  python -m venv venv
  venv\Scripts\activate     # для Windows
  # или source venv/bin/activate  # для Linux/macOS
  ```
- Если VS Code не подхватил окружение, нажмите `Ctrl+Shift+P`, выберите **Python: Select Interpreter** и укажите `venv`.

### 7. Установите зависимости
```bash
pip install -r requirements.txt
```

### 8. Запустите сервер разработки
```bash
uvicorn main:app --reload
```

### 9. Проверьте, что API работает
- Откройте в браузере [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) – должна загрузиться документация Swagger UI.
- В списке эндпоинтов уже есть все CRUD-операции (`GET /tasks`, `POST /tasks`, `PUT /tasks/{task_id}`, `DELETE /tasks/{task_id}`) и три тестовые задачи.

## 💻 Основное задание

### 10. Создайте ветку для новой функциональности
```bash
git checkout -b feature/search-tasks
```

### 11. Добавьте эндпоинт поиска задач по заголовку
Откройте файл `main.py` и перед строкой `if __name__ == "__main__":` (или в любом подходящем месте) вставьте:

```python
@app.get("/tasks/search", response_model=List[Task])
async def search_tasks(q: str):
    """
    Поиск задач по заголовку (регистронезависимый).
    Возвращает список задач, в заголовке которых содержится подстрока q.
    Если q пустая или не передана, возвращает пустой список.
    """
    if not q or not q.strip():
        return []
    results = [task for task in tasks_db.values() if q.lower() in task.title.lower()]
    return results
```

**Не забудьте импортировать `List`** из `typing`, если его ещё нет вверху файла.

### 12. Проверьте работу через Swagger UI
- Убедитесь, что сервер запущен.
- Перейдите в Swagger UI (`/docs`), найдите `GET /tasks/search`, нажмите **Try it out**, введите значение `q` (например, `изучить`) и выполните запрос.
- Должны отобразиться задачи, содержащие это слово в заголовке.

### 13. Закоммитьте изменения


## 🔁 Pull Request и Code Review

### 15. Откройте Pull Request
- На странице **вашего** репозитория на GitHub перейдите во вкладку **Pull requests** → **New pull request**.
- Убедитесь, что `base repository` – это ваш форк, ветка `main`, а `head repository` – ваш форк, ветка `feature/search-tasks`.
- Нажмите **Create pull request**.
- В описании PR напишите: «Добавлен эндпоинт поиска задач по заголовку».

### 16. Пригласите одногруппника на ревью
- В правой панели PR найдите раздел **Reviewers** → нажмите шестерёнку или **Request reviewers**.
- Введите GitHub-логин вашего партнёра.

### 17. Выполните ревью (если вас пригласили)
- Откройте PR товарища, перейдите во вкладку **Files changed**.
- Проверьте код на логику, стиль (отступы, пробелы), наличие докстринга.
- Если всё хорошо – поставьте **Approve**. Если есть замечания – нажмите **Request changes** и напишите комментарии.

### 18. Исправьте замечания (если они были)
- Внесите правки локально в той же ветке `feature/search-tasks`.
- Сделайте коммит (`git commit -m "Fix review comments"`) и запушите (`git push origin feature/search-tasks`).
- PR обновится автоматически. Ответьте ревьюеру комментарием.

### 19. Смержите PR
- После получения апрува нажмите **Merge pull request** → **Confirm merge**.
- Ветку `feature/search-tasks` можно удалить (кнопка **Delete branch**).

## 🧠 Дополнительные задания (по желанию, +2 балла)

Если основное задание выполнено и осталось время, реализуйте один или оба эндпоинта. Работайте в **новой ветке** (например, `feature/patch-task`) и откройте **отдельный PR**.

### 1. `PATCH /tasks/{task_id}` – частичное обновление задачи
- **Описание:** обновляет только переданные поля (заголовок, описание или статус).
- **Метод:** `PATCH`
- **Тело запроса:** JSON с любыми из полей: `title`, `description`, `is_completed` (все опциональны).
- **Требования:**
  - Если задача не найдена – вернуть `404`.
  - Если передан пустой объект – вернуть `400` или текущую задачу без изменений.

**Подсказка:** создайте модель `TaskPatch` з опциональными полями и используйте `model_dump(exclude_unset=True)`.

## 💡 Подсказки и частые ошибки

- **CORS-ошибка** – убедитесь, что в `main.py` добавлен `CORSMiddleware` (он уже есть в шаблоне).
- **Не удаётся открыть PR** – проверьте, что выбраны правильные ветки (`base: main`, `compare: feature/search-tasks`) и что обе ветки находятся в вашем форке.
- **Сервер не запускается** – проверьте, что виртуальное окружение активировано, и вы находитесь в папке проекта.
- **Если ревьюер не откликается** – договоритесь заранее в чате группы. Можно попросить преподавателя выступить ревьюером.
